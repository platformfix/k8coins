# CLAUDE.md design notes

## Purpose

This CLAUDE.md optimizes for the same thing [podium's](https://github.com/platformfix/podium) does: a future agent picking up work on a *public, reputation-bearing* repo without re-discovering constraints that were already worked through once. Unlike podium, k8coins does track its own work in beads (the `.beads/` database in this repo), so the existing "Beads Issue Tracker" block stays - it isn't personal tooling here, it's how this project's own issues are actually tracked, and removing it would just make CLAUDE.md wrong about how to find and claim work in this repo.

## Design decisions

- **Why history was squashed to one commit and made public immediately, rather than after hardening.** Per `k8c-14z.1`'s own description: "public flip happens right after the single baseline commit lands, not after any governance/hardening work - the repo goes public early and the rest of the hardening happens visibly, in the open, via PRs." The epic description names this "Candidate C chosen over B's safer-but-slower option" without detailing what B was - that comparison lives in the original diamond-cascade conversation, not in anything this repo's files carry forward. What is captured: the explicit intent that hardening (governance docs, hygiene enforcement, supply-chain security, e2e CI) is meant to be visible in the repo's own public PR history, not landed quietly before the repo had an audience.
- **Why full supply-chain security parity was chosen over a lighter version, despite k8coins having no elevated cluster permissions.** Per `k8c-14z.6`'s own description, quoting Steve directly: "I want everything there because we are showing how to do things properly." This is a deliberate rejection of scaling security rigor to k8coins's own (low) risk profile - the point is that this repo is a teaching artifact for *how* to do CI/CD and supply-chain security, not just an app that happens to need it for its own sake. SLSA provenance, SBOM attestation, and weekly OpenSSF Scorecard all land regardless of whether k8coins's actual privilege level would otherwise justify them.
- **Why the README stayed inline instead of splitting into `docs/` like podium's.** Per `k8c-14z.7`'s own description, quoting Steve directly: "keep the README lightweight, no docs/ split - it's already thorough and well-written, this is badges-and-links only, not a rewrite." Podium's docs/ split exists because its README would otherwise be too long (architecture, full Helm values reference, supply-chain verification steps); k8coins's README is shorter and was judged not to need the same treatment. This is a per-repo call, not a rule - don't propagate podium's docs/ structure here on the assumption that "more like podium" is automatically better.
- **Why the beads integration block in CLAUDE.md was kept, unlike podium's CLAUDE.md which has none.** Podium doesn't use beads for its own issue tracking; k8coins does - this repo's actual `.beads/` database is where `k8c-14z` and its children live. Removing the block on the theory that "podium doesn't have it" would make CLAUDE.md actively wrong about this repo, not just differently-scoped.
- **Considered and rejected: duplicating the README's architecture diagram or Dockerfile-practices section into CLAUDE.md.** Both already have a canonical home in README.md and would drift the moment one copy got edited and the other didn't. CLAUDE.md routes to them instead.
